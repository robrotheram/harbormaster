# k3s reference environment

This is a fresh, single-node reference installation for
`https://harbormaster.exceptionerror.io`, on context `default` /
`ds9.exceptionerror.io`. It does not import, stop, or alter the local Compose
installation. It is not a high-availability production environment.

## Ownership and dependencies

- `workbench-system`: platform, CloudNativePG PostgreSQL 17, TLS and ingress auth.
- `workbench-egress`: dedicated gateways for project `default`.
- `workbench-reference`: retained workspace state and restricted Sandbox resources.
- `agent-sandbox-system`: upstream Agent Sandbox controller v1.0.9.
- `kata-system`: Kata Containers Helm release `harbormaster-kata`, chart 4.3.1.
- Existing Longhorn 1.11.2, CloudNativePG 1.29.1, cert-manager, Traefik and
  oauth2-proxy remain cluster-owned dependencies.

`foundation.yaml` uses an explicit `harbormaster-retain` Longhorn class because
this cluster has two default storage classes. It uses one replica on the one
available node; Retain prevents PVC deletion from automatically destroying its
volume, but does not provide backups or protection against node/disk loss.

## Bootstrap

Run from the repository root. Confirm `kubectl --context default get nodes`
identifies the intended reference node before applying anything.

```sh
kubectl --context default apply -f deploy/kubernetes/reference/foundation.yaml
kubectl --context default apply -f deploy/kubernetes/reference/project.yaml
```

The project manifest is generated by `render_project.py` with project ID
`default` and namespace `workbench-reference`. Do not reuse its namespace for
other projects. New projects need independent bindings and gateway policy.

Install the exact upstream Agent Sandbox `sandbox.yaml` release asset:

- URL: `https://github.com/kubernetes-sigs/agent-sandbox/releases/download/v1.0.9/sandbox.yaml`
- SHA-256: `3eeb27fa821659593ba92c5454571f08c84abb07096bb9d372c1c6c750f6d7d2`

Review and verify the download, then apply it with server-side apply (the CRD is
large). Apply `../admission.yaml` after its CRD is established. The upstream
controller owns Pod/PVC/Service reconciliation; the application's runtime
controller has only the project RoleBinding in `project.yaml`.

Kata installation changes host/containerd configuration and may restart k3s.
The initial installation was explicitly authorized in a maintenance window.
For a later reinstall or upgrade, use a new maintenance window and the official
`kata-deploy-4.3.1.tgz` release chart with `kata-values.yaml`:

```sh
helm upgrade --install harbormaster-kata ./kata-deploy \
  --kube-context default --namespace kata-system --create-namespace \
  -f deploy/kubernetes/reference/kata-values.yaml --timeout 15m
```

Only `kata-qemu` is installed on the named node; the default container runtime
stays unchanged. The chart owns RuntimeClasses `kata` and `kata-qemu`. **Do not
apply `../runtimeclass.yaml` over this chart-managed class**: its node selector
is for a different installation workflow. Helm uninstall also changes the host
and must not run while workspaces use Kata.

After PostgreSQL is healthy:

```sh
python3 deploy/kubernetes/reference/bootstrap_secrets.py --context default
```

This creates a fresh identity Secret and reuses it on subsequent runs. Service
credentials are copied into only the required namespaces. The PostgreSQL
connection uses certificate verification against the cluster's generated CA.
No secrets are printed, committed, or copied from local development. Re-run after
CNPG credential/CA rotation to refresh the application's Secret, then restart the
control plane in an appropriate maintenance window.

## Images and platform

Wait for the full GitHub container workflow to succeed on the intended commit.
Provide a narrowly scoped `read:packages` token through a secure file, then:

```sh
python3 deploy/kubernetes/reference/configure_images.py \
  --context default --username robrotheram --token-file /secure/pull-token \
  --tag sha-FULL_COMMIT_SHA --output deploy/kubernetes/reference/images.lock.json
```

This resolves all eight required images by digest before installing registry
credentials. The resulting lock file contains no credentials and should be
versioned with the deployment. The optional GoGallery template is published
separately and is not selected by this reference installation.
For subsequent releases, use `--existing-pull-secret` instead of `--username`
and `--token-file` to reuse the cluster's scoped credentials without exporting them.

`gateway-endpoints.json` contains this cluster's three gateway Service IPs.
Re-resolve them if those Services are recreated. Workspace networking deliberately
does not permit the cluster's recursive DNS: fixed gateway IPs allow approved
services to work without opening DNS or direct Internet access. The trusted
platform services continue to use normal cluster DNS.

```sh
python3 deploy/kubernetes/reference/render.py \
  --images deploy/kubernetes/reference/images.lock.json \
  --gateway-endpoints deploy/kubernetes/reference/gateway-endpoints.json \
  --output /tmp/harbormaster-platform.json
kubectl --context default apply --dry-run=server -f /tmp/harbormaster-platform.json
kubectl --context default apply -f /tmp/harbormaster-platform.json
```

The default render keeps workspace starts blocked by
`REQUIRE_VERIFIED_ISOLATION=true`. After live runtime, storage and network checks,
`--allow-unverified-reference` explicitly enables execution for this test
environment. The application still reports isolation/network status as
**unverified**; these manual checks do not implement continuous attestation.
Never describe this setting as verified production isolation.

Gateway policies start in **fixture mode**. Configure real inference/subscription
credentials and external Vault separately before expecting live provider calls.
MCP and the control plane remain ClusterIP-only. Only dashboard HTTPS is exposed,
protected by the namespace-local forward-auth middleware and the existing
`oauth-redirect` sign-in handler. Anonymous requests are redirected through the
existing `https://oidc.exceptionerror.io` authentication service. This is a
shared operator console, not per-user project authorization.
The dashboard independently validates the session cookie with OAuth2 Proxy on
every request and enforces the configured HTTPS origin. Client-supplied identity
headers do not grant access. Configure all three `DASHBOARD_PUBLIC_ORIGIN`,
`OAUTH2_PROXY_AUTH_URL`, and `OAUTH2_PROXY_PUBLIC_URL` values together; this mode
cannot be combined with WorkOS authentication.

## Acceptance and recovery

```sh
python3 -m unittest discover -s deploy/kubernetes/reference -p 'test_*.py' -v
python3 deploy/kubernetes/reference/check_runtime_storage.py
python3 deploy/kubernetes/reference/check_network.py
```

The live probes use unique disposable names and remove only their own Pods/PVCs.
The storage probe uses the existing `longhorn` scratch class with Delete reclaim
policy; production workspace volumes use `harbormaster-retain`. Evidence is
written under ignored `.local/k3s-reference/` and includes the guest kernel,
RWOP second-writer rejection, state retention, and allowed/denied connections.
The network probe verifies denied targets are reachable from the trusted
namespace before testing that the workspace cannot reach them.

Before treating the move as complete, verify dashboard health, anonymous access
rejection, successful authenticated access, a workspace lifecycle, and retained
files after stop/start. The repository's branch seeding and automatic isolation
verification limitations still apply. CSI VolumeSnapshot APIs/controller and an
independent backup destination require separate provisioning before the generic
`backup.sh`/`recover.sh` workflow can be used; Longhorn alone is not that contract.

To pause the reference platform, scale its Deployments to zero. Preserve CNPG,
Secrets and workspace PVCs. Do not delete namespaces, uninstall Longhorn, or
uninstall Kata as a routine rollback. See [operations](../../../docs/operations.md)
for matched metadata/volume recovery and the limits of schema rollback.
